# 本地视觉语言模型打标施工方案

## 1. 接入范围

在现有「AI 打标」和「批量打标」里增加「Ollama 本地视觉模型」。应用由 Tauri/Rust 调用本机服务，首个验收模型用当前机器已安装的 `qwen3-vl:8b-instruct`。模型列表从服务发现，可换用通过能力检查和试跑的其他本地视觉模型。首版由用户管理 Ollama 与模型权重。

当前仓库已有固定任务的 Florence-2 图像描述、多模型选择、裁剪后渲染、建议版本和导出标注。新适配器增加可提示词控制的短语标签和自然语言描述，沿用这些入口。当前批量是浏览器逐张调用，VLM 批量应转为后端持久任务。  
定位见 [打标入口](../src/features/editor/WorkbenchPage.tsx)、[推理分发](../src-tauri/src/tagging.rs)、[标注版本](../src-tauri/src/project/captions.rs) 和 [任务模块](../src-tauri/src/project/jobs.rs)。

## 2. 页面与操作

| 位置 | 交互 |
| --- | --- |
| 设置 → 本地模型 | 在本地权重列表下增加「Ollama 本地视觉模型」卡片。默认地址 `http://127.0.0.1:11434`。点「检测连接」后显示连接状态、服务版本与视觉模型下拉。选模型后可点「试跑」验证实际图像推理，默认使用应用自带的合成图。主页设置和项目设置复用同一组件及应用级配置。 |
| 打标 → 当前图片 | 在现有模型选择器增加「视觉语言模型」分组。选中后显示紧凑的「短语标签／自然语言／两者」选项，默认短语标签。语言默认英文。用「生成建议」发起。结果在标注栏原位显示新增标签、描述和当前标注，支持取消勾选、编辑、追加、丢弃。切图后结果归属原图，返回时可查看。 |
| 打标 → 批量打标 | 保留现有选图流程。在批量弹窗顶部显示「已选 N 张」，再选模型、输出和写入策略。默认「生成建议」，可选「追加到现有标注」。提供「试跑 3 张」查看真实项目中的少量样本，少于 3 张时按实际数量。明确显示「开始打标 · N 张」。 |
| 任务中心 | 显示「已处理 41/100 · 成功 36 · 无新增 3 · 失败 2」。支持暂停、停止、查看失败明细及重试失败项。360 像素窄窗保持选图、任务入口和确认按钮可达，标签和描述区允许换行。 |

单图有未保存人工标注时，发起前走现有保存流程。存在未应用裁剪草稿时，提示「使用已应用裁剪」，提供返回裁剪入口。批量只读取每张图已确认的处理版本。模型错误贴近当前控件，例如「连接不到本机 Ollama」配「重新检测」，「模型不接受图片」配「更换模型」。

## 3. 模型适配器与接口

**模型发现。** Rust 新增 `tagging/ollama.rs` 或同级模块，集中维护 HTTP 客户端与响应结构。连接时调用 `GET /api/version` 和 `GET /api/tags`。对候选模型按需调用 `POST /api/show`，读取 `capabilities` 并要求含 `vision`。以 `/api/tags` 返回的模型名和 digest 作为本地安装记录，排除返回云端标记的条目。运行前再核对已选模型及 digest，尤其是中断恢复和模型更新后。前端只拿模型元数据和可执行状态。  
参考 [Ollama 模型详情](https://docs.ollama.com/api-reference/show-model-details) 和 [官方 API 类型](https://github.com/ollama/ollama/blob/main/api/types.go)。

**本地路由。** Rust 只连接配置校验通过的环回 IP 与端口，禁用代理和重定向。模型名从探测确认的本地清单取值。下载模式、远程地址及 Ollama 凭据不进入该接口。验收时可依官方文档关闭 Ollama 的云功能并断网运行。应用日志仅记录任务、模型、阶段、耗时和错误码，图像字节与请求正文留在本次推理的内存中。  
参考 [Ollama 本地绑定与云功能设置](https://docs.ollama.com/faq)。

**推理请求。** 后端发送 `POST /api/chat`。使用单条用户消息，`images` 放一张 Base64 图片，`stream: false`，`format` 放 JSON Schema，并限制输出长度。`temperature: 0` 作为默认值。解析 `message.content`，校验对象、字段类型、长度和空值。下面是数据结构和形状示例。  
参考 [Ollama Vision](https://docs.ollama.com/capabilities/vision) 和 [Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs)。

```json
{
  "tags": ["red coat", "night street", "neon lighting"],
  "caption": "A person in a red coat stands on a neon-lit street at night."
}
```

- 提示词要求描述图中可见的主体、服装、动作、环境、光线及构图。标签使用便于训练的短语。省略不可从画面确认的信息。项目触发词由现有导出逻辑处理，模型输入和输出均无需注入触发词。
- 双字段协议在三种输出模式下统一。标签模式的描述为空字符串，描述模式的标签为空数组。建议起始上限为 24 条标签，每条 60 个字符，描述 400 个字符。校验选定模式至少一个有效字段。结束原因提示截断、返回 JSON 无效或内容为空时，给出可理解的错误，当前结果不写入标注。
- 基线模型使用 Qwen3-VL 的 Instruct 变体。以后按模型能力支持其他变体，调用侧以结构化响应测试为准，不把模型名写成唯一通过条件。
- 初版保存模型 ID、digest、推理模式、语言、提示词版本、图像处理版本和耗时。提示词使用版本化模板。项目自定义行业词汇或词表可以作为后续扩展点。

**项目内契约。**

| 改动位置 | 实现 |
| --- | --- |
| `model.rs`、`types.ts`、`AppProvider.tsx` | 新增带默认值的应用配置，含启用、本机端口及已选模型。给 `ModelInfo` 增加来源及能力字段，可用模型 ID 独立命名，例如 `ollama:qwen3-vl:8b-instruct`。旧配置读不到新字段时使用默认值。 |
| `commands.rs`、`lib.rs`、`api.ts` | 添加 `ollama_probe`、`ollama_test`。沿用 `models_list` 和 `suggestion_generate`，为生成请求增加可选 `outputMode`、`language`。Rust 根据模型来源分流。运行 HTTP 和渲染的阻塞工作交给后台线程，IPC 返回元数据或结果标识。 |
| `tagging.rs` | 沿用 `ModelRun` 与 `generate` 的共同入口。VLM 的标签走 `tags`，整段描述走 `text`。先调整当前多模型合并对 `text` 的处理，避免 VLM 和 WD14 同选时丢描述。标签按现有归一化规则取并集，存在多个候选描述时分别预览。批量写入默认要求明确一个描述来源。 |
| `project/captions.rs` | 新增追加式应用路径，复用现有标注保存、审核状态回退和质检过期规则。当前 `apply_suggestion` 会把建议值直接交给 `save`，追加功能应先合并后提交。持久化来源沿用 `caption_revisions.model_json`，允许从当前版本追溯建议及输入版本。 |

## 4. 图片、标注和大图库

1. **准备图片。** Rust 按素材 ID 读取项目记录、源文件和已应用裁剪配方，沿用 EXIF、色彩、裁剪与补边处理。复用现有 worker 渲染，传送给模型的代理图建议从最长边 1024 像素起测，JPEG 质量从 85 起测。透明区域的合成沿用已配置背景，仅影响模型代理图。兼容多模型时复用一次裁剪渲染，VLM 可用该图生成较小的代理，保持 WD14 和 Florence-2 的既有输入尺寸策略。暂存文件在开始渲染前绑定清理句柄，失败、取消与成功都可释放。
2. **控制资源。** 批量默认每个本机 Ollama 实例同时处理一张，前台和后台共享推理并发限制。每次只准备当前图片，尽早释放完整图像、代理、编码结果和临时文件。长边限制只约束送给模型的图片，源图解码仍沿用现有大图资源限制。单图渲染走交互优先级，批量渲染走后台优先级。为连接、冷启动推理及响应大小设独立上限，阶段文案区分「准备图片」「等待模型」「正在生成」。批量可配置短时间模型驻留，并用冷启动、热模型和 GUI 响应时间决定默认值。  
3. **合并结果。** 以现有 NFKC、空白与大小写规则去重，保留用户已有标签文本、顺序和停用状态。标签追加到末尾。描述追加保留原段落，按规范化整句或整段去重；避免把输出文本统一按逗号拆成标签。保存模式按最终内容落到 `tags`、`nl` 或 `mixed`。当结果无新增时，保留现有审核状态与修订号。
4. **处理编辑冲突。** 建议记录生成时的项目、素材、源文件身份、已应用裁剪版本及模型配置。用户采纳时在短事务内校验素材仍存在、裁剪和源文件仍匹配，以及编辑预期版本。手工标注改过时可重新读取并重显合并预览，裁剪或源图变化时提示重新生成。参考导入现有的源文件校验，区分正常可读、丢失与内容已变的外部引用。  
定位见 [裁剪渲染](../src-tauri/src/tagging.rs#L597)、[工作进程优先级](../src-tauri/src/worker.rs#L446)、[标注归一化](../src-tauri/src/caption.rs) 和 [标注保存](../src-tauri/src/project/captions.rs#L573)。

## 5. 批量任务的执行和恢复

- 新增 `tagging` 任务类型及 `tagging_job_start`。提交时冻结去重后的明确选区、模型 digest、输出配置及写入策略。任务逐项持久化并分段读取，单独记录待处理、已生成、无新增、冲突与失败。任务详情分页，进度事件只推送统计和当前项，按现有任务模块节流。
- 每张图的结果、计数及完成状态保持一致。只生成建议时，建议版本和记录的状态一起提交。启用追加时，将当前图片的标注写入、来源、历史和任务状态纳入同一个提交边界，或者用等效的幂等键解决中断重试。应用重启后显示「已中断」，恢复仅处理待处理项，重试只处理选中的失败项。模型摘要变化时提示重新确认模型。
- 暂停在当前图完成后生效。停止时取消尚未开始的图片，运行中结果返回后先检查取消状态，再决定是否入库。已经提交的条目保留。连续检测到服务不可用时暂停并引导重新连接，坏图或格式错误单独计失败。
- 生成建议可在任务详情按图片审阅和追加。开启自动追加时，为本批记录每张图提交前与提交后的版本。用针对本批的撤销恢复仍匹配的版本，已被人工再次编辑的图片列为冲突。当前前端通过多次调用全局 `undo` 模拟整批回退，后台任务应使用带目标版本的撤销。
- `JobsDrawer` 展示进度与失败项，`ProjectShell` 按项目 ID 接收事件，避免切到另一项目时刷新错误页面。任务完成后刷新受影响图片及统计。图库、裁剪板和打标工作台在任务运行时可继续使用。  
定位见 [任务恢复与重试命令](../src-tauri/src/commands.rs#L1144)、[任务事件和检查点](../src-tauri/src/project/jobs.rs)、[现有前端批量处理](../src/features/editor/WorkbenchPage.tsx#L1072)。

## 6. 施工顺序与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| A. 本地接通 | 模型设置、能力探测、后台 HTTP、合成图试跑 | 有服务、有视觉模型时通过试跑。服务关闭、文本模型、无模型、输出无效各有对应提示。确认云端模型未出现在可选列表。 |
| B. 单图闭环 | 裁剪图输入、三种输出、建议预览、追加与撤销 | 用带已应用裁剪、透明区域、中文路径和已有人工标注的样本，检查裁剪区域、标签顺序、停用状态、描述标点、触发词和导出结果。并发手改或重裁时保留用户编辑，旧建议可识别为失效。WD14 和 Florence-2 的单模与混用场景回归。 |
| C. 批量与恢复 | 持久任务、试跑、进度、暂停、取消、重试及批次撤销 | 批量选 100 张，混入丢失源文件、重复结果及故意中断。切页、关闭项目重开和重启后核对计数与检查点，确认成功图不会重新追加。用 1 万张项目测跨页选区与大图样本，再测图进程和应用的峰值内存、冷／热推理耗时与图库滚动。 |
| D. 发布包 | Windows 安装后可探测已安装 Ollama，并用发布资源执行图片预处理 | 用干净环境实测已装／未装 Ollama、模型缺失、图像 worker 未就绪、纯离线打标。安装包的资源路径与开发路径分开验证。定量记录耗时与内存，再确定目标机器可接受的默认输入尺寸。 |

图像运行时的发布验证沿用 [性能与发布方案](IMPORT_PERFORMANCE_PLAN.md)。Ollama 自己承担 VLM 的模型运行，原有 Python 图像 worker 继续负责已裁剪图片的生成。

### 本机接口验证

2026 年 11 月 25 日，通过本机 Ollama 0.40.14 的模型接口确认 qwen3-vl:8b-instruct 具备 vision 能力。把程序生成的 192×192 几何图发到环回接口，模型返回可解析的 JSON，包含 10 条标签和一条正确描述红圆、蓝方块与白底的英文句子。请求单次总耗时 77.65 秒，包含当次服务端处理。该结果验证接口和输出形状。真实训练集质量、热模型耗时和安装包内体验由实现阶段验收。模型首次加载和生成的超时应单独调试，设置页试跑可从 180 秒总超时起测。
